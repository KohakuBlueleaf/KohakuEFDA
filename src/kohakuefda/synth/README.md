# kohakuefda.synth

The project netlist as a KohakuLayout problem. The planner and `plan/machines.py` keep
producing the project `Netlist`; the synth turns it into a framework `Problem` for the
Endfield pack, a framework `Layout` back into the project's `Placement` and `Layout`, and
a project `Layout` from any source into a framework problem and layout for the verify
runner.

| file | what |
|---|---|
| `footprints.py` | `footprint_of(machine)`: size from the dataset, every port as a side and offset, machines shade the sky; `ENTRY_FOOTPRINT` for outside inputs; `library_of(dataset, cells)`; `ports_for(fp, pin)`: the pin's default port first, then its alternatives |
| `flows.py` | `Flows`, the wire analysis `Translation` inherits: the net's graph, its orientation (on a tree with rates each step from the side whose share of the supply passes its share of the demand, `tree_orientation`; elsewhere each segment as the router laid it, a lane ending where another lane leaves a source merging into it, a segment ending on a source's attach cell read the other way; `rates` the supply and demand per attach cell) and the flow on every step (on a tree, each pin's supply pushed along the orientation, a sink taking its demand as it passes, a branch sharing evenly, so the pieces follow the tree the router built; `lane_flows` along each lane's path otherwise), interior terminals and junction cells, each junction's kind and rotation from the flows meeting there (a unit the router placed where the flow passes straight through keeps its kind: a repeater is a splitter with one output), pieces oriented by flow with dead pieces dropped; `step_between` and the unit-kind sets |
| `hierarchy.py` | `hierarchical_of(netlist, flat)`: the flat framework netlist folded by the cells' units into one `Module` per top-level tile type (the first copy's cells and inner nets, a `ModulePort` per pin a net leaves through), one instance cell per copy, the nets between copies and the cells built once rewritten onto the ports; `flatten()` gives the flat netlist back with leaves named `<instance>/<leaf>`; `instance_id`, `copies_of`, `paired`, `HierarchyError` |
| `tiles.py` | `tile_problem(hier, module, box)`: a module's body as a problem on a box with a one-cell ring, its port cells pinned to the rim (inputs north, outputs south) and no power needs; `normalised`, `fragment_cells`; `macro_of(hier, module, problem, layout)`: the fragment at the origin with its footprint from `derive_footprint`; `with_macros`: the instances rebound onto macros; `port_sides`, `TileError` |
| `layout.py` | `layout_of(problem, layout, dataset, netlist, assessment)`: a framework layout back into the project's `Placement` and `Layout`; `Translation(Flows)` emits units with computed kinds and rotations, segments with entry and heading, pylons, entries, blocks and the terms; `placed_machines` turns a cell's machines to the placement's rotation and anchor |
| `frames.py` | `FrameObserver` (framework events to the project's schema-1 frames, plus the `catalogue` and `final` frames), `catalogue_of` (every cell's size, kind, group, machines and pins), `LayoutEveryFrame` (a frame with the layout every N charged units of budget: inside a construction attempt as it stands, after an improvement move once it has settled), `Cancel` (the run manager's flag raised at the next attempt) |
| `modules.py` | `modules_of(dataset, layout)`: blueprint-sized modules, tiles of at most 50×50 halved while they hold too many entities |
| `reverse.py` | `problem_of_layout(dataset, layout)` and `Reverse`: a project layout as a framework problem and layout from its geometry alone; every placed machine a cell with the machine's footprint and a pin per port a wire touches (the port's item from the recipe or the config), a covering pylon a `field:power` unit, an outside input an `entry` cell on its border cell, logistics units as the pack's units; `Connections` (a segment starts on the cell an OUT port faces and ends on the cell an IN port faces, the recorded entry and heading first; a unit's port facing another entity's port links directly; a bridge joins across opposite edges only), `components_of` (the segments and units that touch as one wire and net), `params_of_layout` (square and ring from a centred area, else the whole grid with the area as the entry area; the fixed bus and its slots through the origin), the flow facts (`role_of`, `port_specs`, `flow_facts`: each pin's item and rate from the recipe, the source rate or the config; a crafter's needs and products; activation; a dump's items; an inlet's filter; a control port's item), `link_id`, `kl_name` and `project_names` (project ids as framework identifiers and back) |
| `problem.py` | `problem_of(dataset, netlist, board)`: cells with pins, constraints, groups and `needs`, machine facts in `attrs["endfield"]`, the netlist's conduit links in the netlist's; project nets paired into lanes (`lanes_of`; `assign` a staircase, the small sources one to a sink in turn, then the largest sinks first, each filled from the largest sources in order, so a sink takes from few sources and a source feeds few sinks; `closing` with `feeders_of`: a sink takes, whole, a source its own cell feeds, so a return flow closes its loop on the machine it came from; the pins of one repeat unit paired among themselves first) and, on a belt, each source pin's lanes one framework net that only splits, a sink several source pins reach taking each on a copy of its pin with the `COPY` suffix on the same ports (`OWN_PORTS`, `by_source`, `split_lanes`, `nets_of` with the copies per cell, `cell_of` adding them), a pipe's connected set of lanes one net (`components`); groups; the basement as fabric params (`params_of`); `kl_id` and `project_pin_id` map pin ids; a lane net's sources ordered by their load, the root first; a pipe net with several sources and sinks laned as a trunk, joins and branches, every other net best-fit |

Dependencies: `kohakulayout` (`ir`, `engine.plugins`), `kohakuefda.model`, `kohakuefda.layout` (`board`), `kohakuefda.plan` (`depot`), `kohakuefda.physics`.
